## 二、生图功能与后台

### 生成失败排查

- 用户反馈生图页面显示“服务暂时不可用”，要求查明并修复。
- 排查记录指出，应用允许上游请求等待最长 180 秒，而 Nginx 一度使用约 60 秒的默认等待时间；真实模型请求也出现超过应用超时仍未返回的情况。
- 另有本机访问域名 TLS 握手重置及备案拦截页的记录。服务器内部健康检查正常并不能证明用户侧网络或模型生成正常。
- 后续修复了上游 IPv4 连接路径，但模型列表可用、鉴权成功仍不足以证明生图成功。最近一次对话仍将实际生成超时列为未解决问题，待结合上游任务记录或模型服务商进一步确认。

相关材料：[IPv4 修复记录](deployment-image-ipv4-20261008.md)。

### 图片预览与账号云端历史

- 生图结果和历史图片增加放大预览，支持关闭按钮、点击遮罩和 Esc 关闭；聊天记录显示该功能已发布。
- 后续用户明确要求“以后生成的图片能在历史中看见”。最终采用登录账号云历史：新生成图片跨设备保存，可查看、下载或删除；旧的浏览器本地历史保留在原设备，不自动上传。
- 发布检查确认匿名访问云历史和生图接口会返回 401。没有使用真实账号调用付费模型完成端到端生图，因此付费生成链路仍需真实验证。

相关材料：[图片云历史发布记录](deployment-image-cloud-history-20261008.md)。

### 平台账户余额

- 后台增加了按平台配置余额查询接口及 JSON 字段的能力，但 OpenAI 兼容平台没有统一的余额标准。
- 对 VVVOX，聊天中没有找到可验证的账户余额接口文档；`/v1/usage` 不能据此当作余额接口使用。未知接口配置应留空，不能猜测路径。
- 已配置余额接口的平台会在后台打开时立即查询，每 60 秒刷新；页面隐藏或后台锁定时暂停，切回页面后重新查询。手动查询仍保留。

## 四、发布流程与服务器迁移

### 唯一正式发布方式

- 用户明确要求把最新生产发布流程设为项目最高优先级，并移除不必要的并行发布方式。
- 项目现行规则要求：制作经过测试的完整发布包，使用本机已授权 SSH 身份上传，再调用服务器现有的 `release-production.sh`；发布后核验真实线上页面/API 并记录版本、备份和验证结果。
- GitHub Actions 只做 CI，不负责生产发布。不要把推送成功或 CI 成功描述为上线成功。
- 用户后续可直接说：“按项目最高优先级的线上发布流程，把这次改动发布到线上。”

权威说明见项目根目录 [AGENTS.md](../AGENTS.md) 和[生产发布手册](production-release.md)。

### 更换服务器

- 用户询问以后更换服务器是否麻烦。结论是应用代码迁移难度适中，主要工作是迁移 MariaDB、上传文件、运行配置和密钥，重建 Node.js、systemd、Nginx、HTTPS 等环境，再切换 DNS 并保留旧机回退。
- 图片平台配置依赖服务端加密密钥；迁移时必须安全保留，否则已有加密配置可能无法读取。当前脚本含固定服务器和目录假设，更换操作系统或路径需要额外调整。
