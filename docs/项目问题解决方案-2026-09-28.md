## 高危

### 1. MariaDB 下搜索 SQL 语法错误（`ESCAPE '\'`）

**位置**：`backend/database.mjs:407-413`、`backend/content-admin.mjs:328`

**问题**：JS 模板字符串 `ESCAPE '\\'` 生成的 SQL 是 `ESCAPE '\'`。SQLite 可用，MariaDB 默认 sql_mode 下 `\'` 被解析为转义引号，语句报语法错误，前台搜索和后台内容搜索都可能返回 500。

**解决方法**（推荐方案 A）：
- **方案 A：换一个两种数据库都不需要转义的转义符**，例如 `!`：
  ```js
  const escaped = String(filters.q)
    .replaceAll("!", "!!")
    .replaceAll("%", "!%")
    .replaceAll("_", "!_");
  // SQL 中统一写： LIKE ? ESCAPE '!'
  ```
  `content-admin.mjs:328` 同步修改。
- 方案 B：在 `translateMariaSql` 中把 `ESCAPE '\'` 替换为 `ESCAPE '\\\\'`（生成 MariaDB 需要的 `'\\'`）。可行但依赖正则翻译，不如方案 A 直观。
- **补测试**：在 `tests/mariadb-compat.test.mjs` 中断言 `translateMariaSql` 输出不含孤立的 `'\'`；有条件时在 CI 中用 `services: mariadb` 跑一次 `listTools(db, { q: "a_b%" })`。
- **上线后验证**：`curl "https://<域名>/api/v1/tools?q=test"` 应返回 200。

### 2. MariaDB 兼容层阻塞主线程、单连接不重连、超时后结果错位

**位置**：`backend/mariadb-compat.mjs:86-100`、`backend/mariadb-worker.mjs`

**问题**：主线程用 `Atomics.wait` 同步等待每条查询（最长 30 秒），期间整个进程无法处理任何请求；全局只有一个连接，断开后不重连；超时后 worker 迟到的结果会写入共享缓冲区，被下一次调用读到。

**解决方法**（分短期与长期）：
- **短期加固（改动小）**：
  1. **请求序号**：`state` 增加一个 `seq` 槽位，主线程每次调用递增并随消息发送；worker 写回时带上 `seq`，主线程只接受序号匹配的结果，不匹配则丢弃并继续等待或报错。
  2. **超时后重建 worker**：`Atomics.wait` 超时后 `worker.terminate()` 并新建 worker 和缓冲区，避免迟到结果污染。
  3. **自动重连**：worker 中捕获 `PROTOCOL_CONNECTION_LOST`、`ECONNRESET`、`ER_SERVER_SHUTDOWN` 等错误时把 `connection = null` 并重试一次；创建连接时开启 `enableKeepAlive: true`。或改用 `mysql.createPool({ connectionLimit: 1, enableKeepAlive: true })`，由连接池自动处理断线。
  4. 把超时从 30 秒降到 5～10 秒，避免单条慢查询冻结整站。
- **长期方案（推荐）**：数据访问层改为异步接口（`await db.query(...)`），直接使用 `mysql2/promise` 连接池，去掉 SharedArrayBuffer/Atomics 同步桥接。可按模块逐步迁移，先迁移高频接口：`listTools`、`getTool`、`insertEvents`、`getUserBySession`。

### 3. 登录后开放重定向（`next` 参数）

**位置**：`public/auth.js:27-30`

**问题**：只检查以 `/` 开头且不以 `//` 开头，`/\evil.com`、`/%09/evil.com` 能通过校验，浏览器会跳转到外站。

**解决方法**：
```js
const nextPath = (() => {
  const raw = new URLSearchParams(location.search).get("next") || "/";
  try {
    const target = new URL(raw, location.origin);
    if (target.origin !== location.origin) return "/";
    return target.pathname + target.search + target.hash;
  } catch {
    return "/";
  }
})();
```
- 如需进一步收紧，可只允许白名单前缀（`/`、`/admin.html`、`/favorites` 等）。
- 在 `tests/` 中增加用例：`/\evil.com`、`/%5Cevil.com`、`/%09/evil.com`、`https://evil.com`、`//evil.com` 都应回落为 `/`。

### 5. 匿名用户可消耗付费生图额度

**位置**：`server.mjs:1346-1357`（`POST /api/v1/image-generations`）、`backend/image-generation-gateway.mjs:194-203`

**问题**：不需要登录，只按 IP 限制每分钟 20 次、每次最多 4 张；网络传输失败时 POST 会重试最多 4 次，上游可能已经收到请求并扣费。

**解决方法**：
1. **要求登录**：生成接口改为必须带有效会话（`getUserBySession`），未登录返回 401，前端引导登录。
2. **按用户配额**：新增 `image_generation_usage` 表或复用 `analytics_events`，按用户限制每日张数（例如 20 张）；按 IP 保留兜底限流，并把单次 `count` 计入成本：`rateLimit(key, limit, window, input.count)`。
3. **全站预算熔断**：配置 `NIKE_IMAGE_DAILY_BUDGET`，当日总张数超过上限时返回 503，并在后台监控中展示用量。
4. **重试策略**：只在确定请求尚未发出时重试（DNS 失败、`ECONNREFUSED`、TLS 握手失败）；连接建立后出错不再重试，或把重试次数降到 1 次。可以让 `pinnedFetch` 区分"连接前失败"和"连接后失败"两种错误信息。
5. 可选：接入人机验证（极验、Turnstile）防止脚本刷量。

### 8. 生产环境没有定时数据库备份

**位置**：`deploy/nikai-db-backup.service`、`scripts/backup-mariadb.sh`

**问题**：只有 SQLite 备份单元，而且路径 `nikai-ai.sqlite` 与程序默认的 `nike-ai.db` 不一致；生产用 MariaDB 却没有对应的定时任务；由于 `ConditionPathExists` 不满足，任务会被静默跳过。

**解决方法**：
1. 新增 `deploy/nikai-mariadb-backup.service`：
   ```ini
   [Unit]
   Description=Nikai AI MariaDB backup
   After=mariadb.service
   ConditionPathExists=/opt/nikai-ai/.mariadb.cnf

   [Service]
   Type=oneshot
   User=nikai
   Group=nikai
   UMask=0077
   Environment=NIKAI_MARIADB_BACKUP_DIR=/opt/nikai-ai-backups/mariadb
   Environment=NIKAI_BACKUP_RETENTION_DAYS=30
   ExecStart=/opt/nikai-ai/scripts/backup-mariadb.sh
   Nice=10
   NoNewPrivileges=true
   PrivateTmp=true
   ProtectSystem=strict
   ReadWritePaths=/opt/nikai-ai-backups/mariadb
   ```
   配套 `nikai-mariadb-backup.timer`（例如 `OnCalendar=*-*-* 03:30:00`、`Persistent=true`），然后执行 `systemctl enable --now nikai-mariadb-backup.timer`。
2. 修正 SQLite 单元的路径，使其与 `.env` 中的 `NIKE_DB_PATH` 一致；或改用 `EnvironmentFile=/opt/nikai-ai/.env`，让脚本读取同一个变量。
3. **备份失败要能被发现**：给单元加 `OnFailure=`，调用通知服务（邮件或 webhook）；或让后台监控显示"最近一次备份时间"，超过 26 小时标红。
4. 每季度做一次恢复演练（`scripts/restore-mariadb.sh` 恢复到临时库），并记录结果。
5. 可选：把备份同步到异地存储（例如 OSS），避免与数据库同机同盘。

### 9. 伪造 `X-Forwarded-Host` 可改写 canonical、og 和 sitemap 链接

**位置**：`server.mjs:469-473`（`absoluteSiteUrl`）

**解决方法**：
1. 新增配置 `NIKE_PUBLIC_BASE_URL`（例如 `https://www.example.com`），生产环境为必填，缺失时启动失败（与 `NIKE_DB_PATH` 的检查方式一致）。
2. `absoluteSiteUrl` 优先使用该配置；只有在 `trustProxy && isLoopbackAddress(request.socket.remoteAddress)` 时才读取 `X-Forwarded-*`，否则使用 `Host`，并校验其属于 `allowedOrigins`。
3. 删除硬编码的 `47.93.245.219`。
4. 在 Nginx 中显式设置 `proxy_set_header X-Forwarded-Host $host;`，覆盖客户端传来的值。

### 10. 发布失败时数据库结构无法回退、旧发布目录不清理

**位置**：`scripts/release-production.sh:86-88`

**解决方法**：
1. **迁移规范**：采用"先扩展、后收缩"两阶段迁移。每次发布只做向后兼容的改动（加表、加可空列、加索引），删除或重命名放到下一个版本；这样旧代码回滚后仍能在新结构上运行。在 `docs/production-release.md` 中写明这条规范。
2. **回滚预案**：发布前已经有数据库备份（`active-database-backup.mjs`）。在 `release_failed` 中打印这份备份的路径和恢复命令，方便需要时人工恢复。
3. **清理旧目录**：发布成功后只保留最近 N 个（例如 3 个）`previous-*` 目录和快照：
   ```bash
   ls -1dt "$snapshot_dir"/previous-* 2>/dev/null | tail -n +4 | xargs -r rm -rf --
   ls -1t "$snapshot_dir"/release-*.tgz 2>/dev/null | tail -n +11 | xargs -r rm -f --
   ```
4. 发布成功后同时删除 `/tmp/nikai-release-*.sh`。

### 11. 注销账号不需要重新验证身份；Cookie 写接口缺少同源校验

**位置**：`server.mjs:1649-1661`，以及收藏、评分、历史、通知、登出等使用 Cookie 的写接口

**解决方法**：
1. 注销请求体增加 `password` 字段，服务端先用与登录相同的 `scrypt` 比对密码，再执行 `deleteUserAccount`；前端注销弹窗增加密码输入框。
2. 注销成功后删除该用户的全部 `auth_sessions`（如果当前实现还没有这样做）。
3. 对所有依赖 Cookie 的 `POST/PUT/PATCH/DELETE` 统一调用 `assertSameOriginForCookie(request, allowedOrigins)`。建议在路由分发前统一处理：`method !== "GET" && cookies[authCookieName]` 时校验。这是 SameSite=Lax 之外的纵深防御。

### 12. 共享管理令牌存在 sessionStorage；生图配置只接受共享令牌

**位置**：`public/auth.js:397`、`public/admin.js:24`、`server.mjs:1280-1282`

**解决方法**：
1. `/api/admin/v1/image-*` 改为使用 `requireManagementAccess`（管理员账号会话即可），密钥写入类操作再要求 `requireSuperAdmin`。这样生产环境可以保持 `NIKE_ENABLE_TOKEN_ADMIN=false`。

3. 定期轮换 `NIKE_ADMIN_TOKEN`，并在后台审计日志中记录令牌访问来源。

### 13. 存储被禁用时首页整体失效；没有 IndexedDB 时生图页整体失效

**位置**：`public/app.js:1`（以及 `getSessionId`、`getVisitorId`、`saveLocalArray` 等）、`public/image-generation.js:6`

**解决方法**：
1. 在 `app.js` 顶部封装一个安全存储：
   ```js
   const safeStorage = (() => {
     try {
       const s = window.localStorage;
       const k = "__nk_probe__";
       s.setItem(k, "1");
       s.removeItem(k);
       return s;
     } catch {
       const memory = new Map();
       return {
         getItem: (k) => memory.get(k) ?? null,
         setItem: (k, v) => memory.set(k, String(v)),
         removeItem: (k) => memory.delete(k)
       };
     }
   })();
   ```
   全文把 `localStorage.` 和 `sessionStorage.` 的直接调用替换为对应的安全封装。
2. `image-generation.js` 改为延迟且容错地创建历史记录：
   ```js
   let imageHistory = null;
   try { imageHistory = createImageHistory(); } catch { /* 历史功能不可用 */ }
   ```
   渲染和保存历史前判断 `imageHistory` 是否为空；为空时隐藏历史面板并提示"当前浏览器不支持本地历史"，生图功能照常可用。
3. 用 `node:test` 加上 `vm` 模拟 `localStorage` 抛出 `SecurityError` 和 `indexedDB` 为 `undefined` 两种场景，断言脚本仍能完成初始化。

### 14. 静态文件每次请求都同步读取并压缩；scrypt 阻塞事件循环

**位置**：`server.mjs:378-445`、`backend/auth.mjs:11-13`

**解决方法**：
1. **首选**：由 Nginx 直接托管 `public/`，Node 只处理 `/api`、`/r`、`/tools`、`/guides`、`/compare`、`/sitemap.xml` 以及应用路由；开启 `gzip_static` 或 `brotli`，给大文件（ffmpeg wasm）设置长缓存，并在文件名中带版本号。
2. **如继续由 Node 托管**：
   - 进程内缓存 `{ mtimeMs, raw, gzip }`，按 `statSync().mtimeMs` 判断是否失效；gzip 结果只计算一次。
   - 超过 1MB 的文件用 `createReadStream` 流式输出，不再整个读进内存。
   - 支持 `ETag`/`If-None-Match` 返回 304。
3. **scrypt**：改为异步 `util.promisify(crypto.scrypt)`，`registerUser`/`loginUser` 改为 `async`，路由中 `await`；同时对登录增加"按邮箱"限流（例如每个邮箱 15 分钟 10 次），防止分布式爆破。

### 15. Python 测试和 lint 从未在 CI 中运行

2. 增加 ESLint（`eslint.config.js` 使用推荐规则加 `no-undef`、`no-unused-vars`），在 CI 中执行 `npx eslint server.mjs backend scripts public --ignore-pattern public/games public/assets/vendor`。
3. 发布脚本 `release-production.sh` 与 CI 使用同一组检查命令（可以抽成 `npm run verify`）。
