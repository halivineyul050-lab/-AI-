# NeStudio 原生小程序 A+B 实施与验收

2026-10-21。本地实现完成，未发布生产；微信侧实测存在下述明确外部依赖。

## 已接入的流程

- 新建项目选择网页/微信，044迁移持久化目标，旧项目默认网页。版本、任务、检查点和续跑按项目目标校验，不能跨目标使用。
- 原生生成独立规划及单文件提示，产出 app.json/app.js/app.wxss/project.config.json 和页面 JS/JSON/WXML/WXSS；结构、资源引用与脚本语法检查；失败进行有界修复，复用逐请求Token账本与积分结算。
- 工作台展示文件与纯文本源码，分别标明结构通过、微信编译待完成、手机业务待完成。原生目标不走网页 iframe、托管发布、域名绑定或网页表单接口。
- 微信发布面板保存 AppID、版本说明与作者手工准备项，提供注册、开发者工具、真实预览、上传、提审及发布步骤。手工勾选不等于微信结果。
- 导出完整原生ZIP，按保存的AppID生成安全工具配置，注入平台自带CLI脚本和README。没有AppID时仍可下载；扫码/上传需真实AppID。
- 本地CLI使用官方 node.exe/cli.js 和参数数组，禁用 shell；doctor、islogin、preview、upload 独立命令，上传必须显式指定版本/说明。二维码检查文件全新、完整PNG/CRC和有界解压，不能以旧图、截断图片或进程失败冒充成功。有效图片不等于已成功扫码。
- 当前原生生成范围为主包、基础组件、静态功能和本地存储；业务登录、支付、网络/云后台尚未接入，不以本地保存或成功弹窗冒充真实业务提交。

## 验证

- Node 22.18.0（生产同版本）最终全量：867项，864通过、3跳过、0失败。
- 独立审阅复核及27项测试通过；发现并修复wx别名绕过、WXSS资源漏检、原生错误依赖网页预览就绪状态。另修复AppID大小写、CLI截断PNG误报、原生生成提示冲突和标准app.json.window配置误报。
- 新增测试覆盖原生目标/版本/检查点隔离、逐文件生成与结构修复、AppID保存与导出、跨用户拒绝、源码不执行、网页兼容、无AppID提示、手机宽度及无外键时新表注销清理。
- 实际临时后端 + 隔离浏览器使用真实模型工程，8文件源码可见，发布准备POST HTTP200，正确列出待填写AppID和手工检查项；页面无JS错误，390px无横向溢出。验收服务器使用显式同源白名单，没有为测试关闭CSRF。
- 最后的表单验收发现AppID被浏览器设为必填，阻止无AppID先保存准备信息；已取消此必填限制，并对齐版本/说明长度。原生与计费界面6项专项回归通过，实际后端空AppID保存PUT HTTP200。此项在上述全量之后以专项及真实浏览器复测。
- 本机官方工具doctor通过。islogin实际调用超时，未声称已登录或编译成功。用户明确“还没有AppID”，未生成真实微信二维码、上传、提交审核或发布。
