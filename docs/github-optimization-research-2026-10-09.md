# 泥壳 AI 工具站：GitHub 同类项目调研与优化建议

调研日期：2026-10-09（Asia/Shanghai）。本次产出为调研建议，未修改业务代码或发布生产。

## 判断

泥壳已有分类、搜索、筛选、收藏、对比、任务导购、教程、资讯、投稿、周报，以及工具详情、专题和对比的 SEO 页面。下一轮应优先提高用户找到合适工具的准确性，以及信息的可信度与新鲜度。

以下区分三类证据：GitHub 仓库公开声明、本地代码现状、浏览器实际看到的生产页面。仓库功能描述不代表已经运行其项目或核验其目录内每条产品资料；本地代码也不自动代表生产版本。

## 本站当前发现

### 1. 先核对生产页面与本地版本

本次浏览器打开 https://ontimo.cn/ ，页面显示已收录 6330 个工具、16 个场景分类，目录首次展示 24 个工具。这是该次访问时的页面值，不是对全部数据的审计。

首页“AI 圈最近有什么新鲜事？”显示三篇日期为 2026-09-14 至 2026-09-16 的内容；页面其他资讯区存在更多文章，但本次没有逐条核实新闻事实和发布时间。对于 10 月 9 日访问者，这个开场区的新鲜度需要检查。

本地 index.html 与 app.js 已包含首页 home-hot-list 和 /api/v1/news/hot 读取逻辑；本次生产页面观察到的首页文案和内容组织与之不同。后续实施前需核对完整生产基底、实际返回的 HTML/JS 及缓存，不能仅凭本地文件断言线上已有同样行为，也不能现在断言差异由缓存造成。

### 2. 日期与信息质量标签需要分开

本地 backend/database.mjs 的公开工具对象把 content_updated_date 映射为 updated，并保留 quality；数据表已有 last_verified_at。工具列表卡片把 updated 用于“资料核验于”文案，对应详情/对比还用于资料更新展示。这几个日期含义需要明确。

建议：收录时间表达首次入站，更新时间表达资料变化，核验时间只表达实际复核。未经核验显示“待核验”，旧核验标记“建议复核”。核验标识不能仅由内容更新日期产生。

### 3. 首页“最新收录”与目录分页存在耦合

本地 renderHomeSections() 从当前 tools 数组按 updated 排序，生成“最新收录”。这只能给出当前加载集合中的更新排序，且更新时间并不等于首次收录时间。

建议：首页热门、最新收录、最近更新分别使用明确的数据来源；首页推荐不要随目录搜索或分页结果变动。“最新收录”按首次发布/收录时间，“最近更新”按资料变化时间。

### 4. 搜索与分享路径还有提升空间

本地 listTools() 用整个查询字符串做 LIKE 匹配名称、简介、描述、分类、能力、场景和标签；本地离线筛选也使用 includes。已有多字段匹配，但还可补同义词、工具别名、多词匹配和相关性排序。

loadInitialState() 已可读取 q、category、price、platform、lang、sort 等参数；常规筛选和搜索是否完整写回 URL、刷新和后退是否恢复，需补交互验证。无需把“支持 URL 参数”当成新功能重做。

### 5. 对比已具备基础，可以更接近真实决策

本地对比弹窗已有价格类别、分类、平台、语言、核心能力、账号要求、地区和更新时间。下一步应补免费额度、主要限制、来源与真实核验日期，按用户场景解释适合谁，并突出差异。

SoftwareApplication、ItemList、BreadcrumbList 和动态 sitemap 已在 server.mjs 实现。因此 SEO 下一轮应补真实页面内容、内链和日期语义，而不是重新增加基础结构化数据。

## 推荐实施顺序

以下为本项目建议，不声称参考项目都已实现这些改进。

| 顺序 | 优化包 | 具体结果 | 验收方式 |
| --- | --- | --- | --- |
| 第一批 | 核验标识与首页数据正确性 | 核验日期独立展示；未知信息不推断；热门、最新收录和最近更新各自有稳定来源；首页热点时间与排序清楚。 | 人为构造不同收录/更新/核验日期，检查每处显示；改变目录筛选，首页栏目保持各自语义；热点成功、空结果和失败均可正常阅读。 |
| 第二批 | 搜索与筛选体验 | 维护中文任务词和工具别名，如“做 PPT/演示文稿”；多词搜索按相关性排序；当前条件可见、可单独清除，结果可分享，刷新/后退可恢复。 | 固定查询集合，记录修改前后的结果与空结果率；检查 q、语言、价格、平台组合；连续输入和清空后最后一次查询获胜。 |
| 第三批 | 有来源的工具详情与对比 | 快速判断区展示价格说明、账号、访问条件、免费限制和来源；对比突出不同项；推荐附场景依据。 | 同一工具在卡片、详情、对比与 SEO 页取值一致；未知字段都显示待核验；来源可访问。 |
| 第四批 | 工作流专题与回访 | 把已有“短视频创作线”等组合升级成步骤：文案→配音→生成→裁剪，每步连教程、外部工具和本站处理工具；逐步支持收藏分组和最近使用。 | 从具体任务进入能走完整路径；收藏分组和历史保存需明确本机/账号范围；不展示虚构讨论或使用人数。 |
| 第五批 | 目录维护与性能 | 失效链接/改名复核、资料过期队列；按职责拆分主站脚本，首页只装配所需内容；测量图片/视频工具首次大资源加载成本。 | 发布前检查重复 slug、质量状态和失效链接；性能使用相同设备与网络对比；加载顺序不破坏现有搜索、抽屉和账号流程。 |

第一批应优先于再次整站换皮。已有“小报”风格可延续，设计调整集中在搜索可见性、卡片关键信息、筛选状态和移动端对比阅读。

## 追踪是否有效

复用现有埋点，先建立基线，再按同类访问来源和设备比较：搜索空结果率、搜索后详情打开率、详情到官网点击率、对比后官网点击率、专题进入工具率。没有现成基线时不承诺固定提升百分比。

## 实施与发布边界

目前工作区存在大量未提交与未跟踪文件；本次只增加这份报告。后续编码应以审阅过的范围实施，具体用例随变更补充。

正式发布严格遵守 AGENTS.md 与 docs/production-release.md：核验当前生产完整版本，只叠加本次审阅文件，测试完整发布包，使用已授权 SSH 上传并调用服务器现有 release-production.sh，随后核实真实页面/API。参考仓库的部署方式不替代本站生产发布规范。

调研限制：未运行参考仓库、未验证其每项产品事实、未做跨设备性能基准；GitHub 公共 API 本次触发限流，因此未取得可依赖的完整提交活跃度统计。部分搜索发现的旧目录仓库直接访问为 404，未纳入推荐。
