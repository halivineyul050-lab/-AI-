# AI 兴趣小报前端改版实施计划

> **For agentic workers:** 在当前已确认方向的工作区内按阶段实施；每个阶段保留可独立审阅的页面改动。

**Goal:** 将泥壳 AI 工具站用户端整理成轻松的 AI 兴趣小报体验，让用户容易发现真实热点、工具、教程和游戏。

**Architecture:** 保持原生 HTML/CSS/JavaScript 与现有静态页面/客户端视图。主站复用现有热点 API、文章抽屉和工具数据；共享导航继续由 `scripts/frontend/site-navigation.json` 与模板生成。页面组通过已有设计 token 和自身样式层表达统一的小报语言。

**Tech Stack:** 原生 HTML、CSS、JavaScript、Node.js 静态导航生成脚本。

## 全局约束

- 保留所有现有公开 URL、表单、DOM ID、`data-*` 业务钩子和页面交互。
- 只用真实工具、资讯、游戏和账号数据；不新增虚构社区帖子或互动。
- 不新增 API、数据库表、依赖、前端框架或生产发布通道。
- 保留浅色/深色主题、键盘焦点、触屏可用性和 reduced-motion 支持。
- 仅修改本计划明确列出的用户端前端文件；不得覆盖其他未提交改动。
- 不运行自动化测试或发布生产。

## 文件职责映射

- `public/index.html`：主站首页和内容视图的语义结构。
- `public/app.js`：热点数据读取、热点卡片渲染和现有内容交互。
- `public/assets/css/site/site-catalog.css`：首页小报头版、热点和工具目录布局。
- `public/assets/css/site/site-content.css`：资讯、教程、榜单等编辑式内容版式。
- `public/assets/css/site/site-responsive.css`：主站桌面/移动导航和响应式修正。
- `scripts/frontend/site-navigation.json`、导航模板与 `scripts/build-site-navigation.mjs`：所有静态页面共享导航源和输出。
- `public/utility-theme.css`、工具专属 CSS：图片、视频、实用工具工作台外观。
- `public/games.html`、`public/games.css`、`public/game-shell.css`：游戏目录与游戏外壳。
- `public/auth.css`：账号登录和个人中心。

## 阶段 1：主站首页与导航

- 首页将主视觉改成轻松的小报开篇，保留原搜索表单、热词、目录数和核验说明的业务节点。
- 增加首页热点列表/空状态 DOM，复用现有新闻热点读取、文章映射和详情抽屉；列表展示少量热点并提供完整资讯入口。
- 将首页热点区、热门工具和最新收录组成清楚的内容顺序；状态文案分别覆盖 API 读取中、无结果和失败。
- 收整桌面导航可见项目与间距；确认视频价格、AI 生图、小工具、小游戏、分类、收藏和对比仍可到达。
- 修复 390px 下 header、hero 搜索、统计和筛选的最小宽度/换行溢出。
- 核对本阶段修改仅涉及上述主站文件与导航生成文件。

## 阶段 2：资讯、榜单与内容视图

- 在 `site-content.css` 中统一栏目标题、索引标签、卡片节奏和来源信息层级。
- 使多站热点、文章列表、排行榜和教程卡片拥有同一套细节语言，同时保留列表/表格等适合内容类型的原结构。
- 检查主站客户端内容视图没有横向溢出，操作区在手机端可换行/横向滚动。

## 阶段 3：创作与实用工具工作台

- 在 `utility-theme.css` 中统一工具页标题、引导标签、上传区、预览面板和主要操作的视觉层级。
- 分别检查图像本地处理、服务器 AI 处理、视频处理、链接提取和价格比较页，不更改其处理方式或数据流。
- 收整移动导航、控件宽度和长文件名/提示文本换行。

## 阶段 4：游戏与账号

- 在 `games.css` 与 `game-shell.css` 中加强目录的轻松游乐场氛围；保留各游戏玩法色彩、控制和 HUD。
- 在 `auth.css` 中明确登录安全感与个人中心收藏/历史分区；保持注销、权限和账户交互。
- 在 390px 下核对手机页面结构无需横向滚动。

## 完成核对

- 按设计稿的六项验收标准逐项检查页面文件和选择器。
- 对更改过的 JavaScript 运行 Node 语法检查，不运行自动化测试。
- 汇总修改文件、各页面范围和未能完成的项；不把本地实现称为已上线。

## 计划自检

- 设计稿中的首页热点 API 成功/空结果/失败有阶段 1 的具体实现项。
- 导航入口、响应式、用户端各页面组、主题、焦点、动效和既有交互均分配到实施阶段。
- 不修改 API/数据库、账户权限或游戏逻辑；后台明确排除。
- 全局约束与任务范围一致，没有待定占位内容。
