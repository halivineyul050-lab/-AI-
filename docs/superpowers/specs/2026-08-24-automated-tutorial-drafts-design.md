# 实用教程自动草稿设计

日期：2026-08-24

## 目标

在不影响现有 AI 资讯采集器的前提下，每 48 小时自动选择一个实用教程主题，生成一篇 800–1500 字的教程草稿。所有自动教程只进入后台草稿箱，必须经过人工审核才能发布。

## 范围

本次包含教程选题、来源采集、去重、AI 生成、内容校验、草稿保存、调度状态、日志和测试。不包含自动发布、自动截图、付费内容、邮件提醒和新的后台编辑器。

## 总体架构

网站 Node 服务保留现有资讯调度器，并增加独立教程调度器：

```text
网站服务
  ├─ 资讯采集器：每 6 小时运行，生成资讯并自动发布
  └─ 教程采集器：每 48 小时运行，生成教程并保存草稿
```

两个采集器共享 AI 客户端和环境配置，但分别维护来源、提示词、去重规则、状态和输出策略。教程逻辑不得直接塞入资讯采集器的分支中。

## 配置

教程采集器默认复用：

- `OPENAI_API_KEY`
- `NIKE_NEWS_BASE_URL`
- `NIKE_NEWS_API_PATH`
- `NIKE_NEWS_AI_MODEL`
- `NIKE_NEWS_REASONING_EFFORT`
- `NIKE_NEWS_DISABLE_RESPONSE_STORAGE`

新增教程专用开关和周期配置：

- `NIKE_AUTO_TUTORIALS=false`：默认关闭，显式开启后运行。
- `NIKE_TUTORIAL_INTERVAL_MINUTES=2880`：默认 48 小时，最低 60 分钟。

教程与资讯共用接口并不代表二者共用调度状态。教程任务的上次成功时间单独持久化。

## 选题策略

采用混合选题：

1. 常规情况下，从站内 `enriched` 或 `verified` 且已发布的工具中选择候选。
2. 近期资讯出现明确热点时，允许提高相关站内工具或任务主题的优先级。
3. 选题必须指向一个可验证的具体结果，例如“使用某工具完成会议纪要整理”，不得生成泛泛的产品介绍。
4. 工具官网不可访问、缺少官方说明或无法核验操作步骤时，跳过该候选。

来源优先级为工具官网、官方文档、官方更新公告，其次是可信的公开资料。第三方资料只能补充背景，不能作为关键操作步骤的唯一依据。

## 去重与节流

每轮最多创建一篇草稿。生成前执行以下检查：

- 如果存在由自动教程任务创建且仍为 `draft` 的教程，本轮以 `pending_draft_exists` 跳过。
- 排除已经使用相同主要来源的教程。
- 排除相同工具与相同任务组合。
- 对候选标题和既有教程标题做规范化相似检查，避免近义重复。
- 任务成功时间写入数据库。服务重启后按持久化时间计算下一次执行，不因重启重复生成。

人工将草稿发布或归档后，下一轮才允许创建新草稿。

## 教程结构

教程继续使用现有 `articles` 数据结构：

- `kind = tutorial`
- `status = draft`
- `topic`：写作、图像、视频、编程、办公等主题。
- `title`：以具体任务和成果为导向。
- `excerpt`：说明读者最终能够完成什么。
- `body`：800–1500 个中文字符范围内的结构化正文。
- `sourceUrl`：主要官方来源。
- `source = AI自动采编 · 待人工审核`
- `date`：生成日期。
- `readTime`：预计阅读时间。

正文必须依次包含：

1. 适用场景
2. 准备工作
3. 操作步骤
4. 参数或提示词示例
5. 常见问题
6. 结果检查
7. 来源与核验日期

## 数据流

1. 调度器检查功能开关、48 小时周期和待审核草稿。
2. 从数据库读取高质量工具、既有教程和近期资讯。
3. 建立候选池并执行来源可访问性检查。
4. 读取候选的官方页面和官方文档，限制传入模型的文本长度。
5. 将来源、固定教程结构和禁止编造规则发送给 AI 接口。
6. 解析结构化响应并执行内容质量与编码检查。
7. 再次执行来源和重复检查，避免生成期间发生竞态。
8. 通过现有内容管理层创建教程草稿并记录审计操作。
9. 写入结构化结果日志和持久化调度状态。

## 审核流程

后台沿用现有文章编辑能力。审核者可以修改标题、摘要、正文、封面和来源，然后发布、继续保留草稿或归档。

自动任务不得把草稿改为已发布，也不得修改人工已经编辑过的教程。自动生成草稿的审计 actor 使用固定标识 `auto-tutorial-publisher`。

## 内容质量门槛

满足以下全部条件才允许写入草稿：

- 标题、摘要、正文和阅读时长均存在。
- 正文长度为 800–1500 个中文字符。
- 七个必要章节齐全且顺序明确。
- 至少存在一个 HTTPS 官方来源。
- 正文不得包含替换字符 `�`、明显乱码、HTML 错误页或未解析 JSON。
- 操作步骤不得包含来源无法支持的版本号、价格、额度或功能承诺。
- 状态必须固定为 `draft`。

## 错误处理

- 单个来源失败：记录警告并尝试下一个候选。
- 所有来源失败：以 `no_valid_sources` 跳过，不创建内容。
- AI 返回 403、502、524 或超时：记录接口错误，不写入数据库。
- AI 返回非法 JSON、缺少章节或乱码：记录校验错误，不写入数据库。
- 存在待审核草稿：记录正常跳过，不视为系统故障。
- 数据库写入失败：事务回滚，保留上次成功调度时间，允许后续重试。

日志不得包含 API 密钥、完整请求正文或管理令牌。

当前 `api.paient.xyz` 对服务器存在 403，并出现 524 和中文编码问题。实现必须安全失败；接口恢复前不得为了满足周期而保存不合格草稿。

## 测试与验收

新增自动化测试覆盖：

- 默认关闭和显式开启。
- 默认 2880 分钟周期与最低周期限制。
- 启动检查和持久化调度状态。
- 混合选题候选排序。
- 相同来源、相同工具任务和相似标题去重。
- 存在待审核自动草稿时跳过。
- 每轮最多创建一篇内容。
- 创建内容固定为 `kind=tutorial` 和 `status=draft`。
- 七个必要章节和 800–1500 字校验。
- 403、502、524、超时、非法 JSON 和乱码时不写数据库。
- 资讯调度器行为和现有测试不受影响。

验收时运行完整测试套件，并用受控测试接口执行一次成功草稿和一次失败请求。成功轮次只能新增一篇草稿；失败轮次不得改变文章数量。服务重启后不得立即重复创建草稿。

## 明确不做

- 不自动发布教程。
- 不在存在待审核自动草稿时继续堆积内容。
- 不使用无法核验的第三方内容生成关键步骤。
- 不为绕过供应商限制保存乱码或残缺内容。
- 不在本次改动中重构资讯采集器之外的无关模块。
