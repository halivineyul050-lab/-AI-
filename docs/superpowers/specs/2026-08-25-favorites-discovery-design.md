# 收藏入口与收藏视图设计

日期：2026-08-25

## 背景

当前收藏功能可以正常工作：工具 ID 写入浏览器 `localStorage` 的 `nike-favorites`，顶部书签按钮可切换 `favoritesOnly`，URL 会写入 `?favorites=1`。问题是用户无法理解顶部无文字书签图标就是收藏入口，也没有独立、可直接访问的收藏视图。移动端小于 480px 时收藏数量被隐藏，发现性进一步下降。

## 目标

让用户在收藏后立即知道去哪里查看，并能通过稳定 URL 打开收藏列表；保留现有匿名本地收藏机制，不恢复账号系统，不增加后端或数据库改动。

## 范围

### 包含

- 新增稳定路由 `/favorites`，使用现有工具库列表渲染收藏项。
- 桌面端顶部书签入口显示“我的收藏”和数量。
- 移动端导航增加“我的收藏（数量）”入口。
- 收藏成功提示提供可操作的“查看收藏”。
- 收藏视图提供标题、数量、空状态、返回工具库和清空收藏。
- 收藏仍保存在当前浏览器 `localStorage`。
- 页面明确说明“收藏仅保存在当前浏览器”。
- 继续支持旧 URL `/?favorites=1`，初始化时规范化为 `/favorites`。

### 不包含

- 不恢复登录、注册或账号中心入口。
- 不同步服务器端收藏。
- 不修改现有账号收藏 API。
- 不增加收藏分组、标签、分享或导出。
- 不重构工具列表、筛选、分页或导航架构。

## 交互设计

### 入口

桌面顶部入口使用书签图标、文字“我的收藏”和数字。数字为本机收藏总数，不是当前筛选结果数。点击后进入 `/favorites`。

移动端在导航抽屉中增加“我的收藏”，并显示数量。小屏顶部可以继续只显示书签图标，但移动菜单必须提供有文字的入口。

### 收藏操作

用户在卡片或详情抽屉点击收藏：

- 按钮立即变为已收藏状态；
- 数字立即更新；
- Toast 显示“已收藏 {工具名}”，附“查看收藏”操作；
- 点击该操作进入 `/favorites`。

取消收藏时 Toast 只显示“已取消收藏 {工具名}”，不提供跳转。

### 收藏视图

收藏视图复用现有工具库卡片与数据加载逻辑，页面顶部增加：

- 标题“我的收藏”；
- 当前收藏数量；
- 说明“收藏仅保存在当前浏览器”；
- “返回工具库”；
- 有收藏时显示“清空收藏”。

分类、价格、平台、语言和排序继续可用，但不能静默退出收藏视图。收藏视图 URL 始终为 `/favorites`，筛选参数可以附在其后。

### 空状态

没有收藏时显示：

- 标题“还没有收藏工具”；
- 说明“浏览工具时点击书签，即可在这里集中查看”；
- 按钮“去工具库看看”。

从收藏视图移除最后一项时，原地切换为空状态，不跳回首页。

### 清空收藏

“清空收藏”只在数量大于 0 时显示。点击后使用原生确认对话框，文案为“确定清空当前浏览器中的全部收藏吗？”。确认后清空 `nike-favorites`、更新所有计数并显示空状态；取消不改变数据。

## 路由与状态

`resolveDestination()` 增加 `/favorites` → `{ view: "tools", favoritesOnly: true }`。初始化时若检测到旧参数 `favorites=1`，通过 `history.replaceState` 规范化为 `/favorites`，保留其他筛选参数。

`updateUrl()` 在 `state.favoritesOnly` 为真时使用 `/favorites`，否则沿用现有工具库或分类路径。任何导航到普通工具库、首页任务卡或分类页的操作继续显式将 `favoritesOnly` 设为 false。

收藏数据继续由 `readLocalArray("nike-favorites")` 和 `saveLocalArray("nike-favorites", state.favorites)` 管理。收藏视图不调用账号收藏 API。

## 组件与代码边界

- `index.html`：添加顶部文字、移动端入口、收藏视图标题栏与空状态操作。
- `styles.css`：收藏入口、视图标题栏、移动端数量与 Toast 操作样式。
- `app.js`：路由解析、URL 同步、收藏视图渲染、清空操作、Toast 跳转与计数同步。
- `tests/catalog-data.test.mjs`：验证收藏路由、入口与静态结构存在。
- 新增 `tests/favorites-ui.test.mjs`：对收藏状态函数和 URL 行为做静态/可执行测试；不引入第三方浏览器测试依赖。

不修改后端、数据库 schema、迁移、认证和管理后台。

## 错误处理

- `localStorage` 内容损坏时沿用现有安全读取行为，按空收藏处理。
- 收藏中的工具已下架或不存在时不渲染该项，但顶部数量应在加载后清理为有效工具数量并写回本地，避免永久显示幽灵收藏。
- 工具接口加载失败时沿用现有重试状态，不清空本地收藏。
- 清空收藏必须经过确认，避免误操作。

## 可访问性

- 顶部入口保留 `aria-label="我的收藏"`，当前处于收藏视图时设置 `aria-current="page"` 和 `aria-pressed="true"`。
- 收藏按钮继续维护 `aria-pressed` 与“收藏/取消收藏”标签。
- Toast 中“查看收藏”为真实按钮，可键盘聚焦。
- 清空收藏、返回工具库和空状态 CTA 均使用原生按钮。

## 验收标准

1. 收藏任一工具后，顶部和移动端数量立即从 0 变为 1。
2. 收藏成功 Toast 中点击“查看收藏”进入 `/favorites`。
3. 直接访问 `/favorites` 可以显示当前浏览器已收藏工具。
4. 刷新 `/favorites` 后收藏仍存在。
5. 在收藏视图取消最后一个收藏后显示空状态，不跳转。
6. 清空操作取消时保留数据，确认时清空并更新所有计数。
7. 旧链接 `/?favorites=1` 自动规范化为 `/favorites`。
8. 480px 以下移动菜单存在带文字的“我的收藏”入口。
9. 不登录也能完成收藏、查看和清空。
10. 现有搜索、筛选、对比、详情抽屉与工具官网跳转测试继续通过。

## 成功指标

埋点沿用 `tool_favorite`，新增 `favorites_view`、`favorites_clear` 和收藏 Toast 来源参数。上线后观察收藏后进入收藏视图的比例、收藏用户后续官网跳转率，以及收藏视图空状态点击率。
