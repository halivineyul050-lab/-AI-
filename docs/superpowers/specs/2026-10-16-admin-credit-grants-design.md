# 后台直接派发积分

用户已要求可向已有账户直接派发积分，并要求继续完成。沿用现有积分管理权限和同源校验，在积分管理内使用完整邮箱或账户 ID 查找账户，显示身份、余额和冻结数；填写正整数积分和必填备注后提交。

派发使用请求唯一编号。钱包增加、流水和记录在同一事务提交；重试同一请求只返回原结果，内容改变返回409；不提供扣减余额功能。记录保留账户、金额、备注、操作人和时间，用户流水显示管理员派发。金额与总余额上限10亿，账户必须存在。数据库迁移038兼容SQLite和MariaDB。

验收覆盖接口权限、余额上限、异常回滚、重复和并发请求、真实浏览器失败后重试、保存NeStudio固定价格兼容。真实生产不替用户任意派发积分，验收仅使用临时测试账户。
