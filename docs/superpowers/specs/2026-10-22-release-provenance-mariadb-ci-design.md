# 发布凭证与真实MariaDB CI设计

2026-10-22。用户已同意优先实施版本管理固定流程与真实MariaDB CI。

发布管理采用本地离线工具，沿用生产完整快照作为基底，只允许指定Git提交中的白名单覆盖。核验完整目录的缺失、多余、敏感路径、链接、逐文件摘要；绑定发布ID、提交、基底ID和发布包摘要。封包核验实际tar成员与内容，不只记摘要。发布成功后的记录必须包含备份路径、success、健康结果。工具不上传、不切换、不提供另一条发布通道，也不修改服务器现有脚本。

CI独立MariaDB10.5.29 service，显式loopback高端口、专用CI变量和随机nikai_verify库名；不加载.env，拒绝继承NIKAI_DB配置。复用现有真实资讯验证器，完成后无论成功失败均尝试删除自建库并关闭连接。普通单元测试不连接真实库。CI只测试，不部署。

备选方案：仅维护人工清单成本最低但易漏项；新增部署平台超出范围且违反唯一SSH通道。采用离线凭证工具加现有Actions服务容器，保持部署职责不变。

验收：白名单外变化、错提交、敏感文件、篡改归档被拒绝；成功与失败清理生命周期均有测试；完整本地测试与实际GitHub MariaDB任务通过。原先三个保留目录不再操作。
