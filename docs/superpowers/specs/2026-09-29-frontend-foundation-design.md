# 前端统一与结构整理设计

日期：2026-09-29

## 目标

让泥壳AI工具站的前台页面在导航、主题、排版和基础控件上保持一致，同时让前端代码按职责清晰归属，减少每次新增页面时继续追加覆盖样式或复制不同版本导航的情况。

继续使用原生 HTML、CSS、JavaScript 多页架构。保留现有公开 URL、静态页面交付方式、API、DOM 选择器和业务行为，不把整理工作扩大成前端框架迁移或业务重写。

## 当前问题

- `public/design-system.css` 与 `public/styles.css` 都定义设计变量，主题、圆角、间距和控件规则存在多个入口。
- `public/styles.css` 和 `public/admin.css` 持续累积页面规则及后置覆盖，难以确认某个页面最终使用哪条规则。
- 主导航、站点页头和主题控制散落在多个静态 HTML 中；工具、游戏、认证、后台各有自己的组合方式。
- 前端资源除 `public/games/` 外多集中在 `public/` 根目录，首页、工具、游戏和管理界面的页面入口与资源边界不够直观。
- 现有设计方向和文档已经定义紫色品牌系统，但各页面没有稳定地消费同一套规则。

## 设计原则

1. 以现有紫色设计系统为基础，清理重复定义和后置补丁；本次不重新发明品牌视觉。
2. 把共享规则集中到唯一的设计变量和基础组件层，页面专属样式只负责该页面的布局和交互状态。
3. 将页面按主站与内容、图片/视频工具、小游戏、认证、运营后台分组。各组的入口、样式和脚本职责清楚可查。
4. 共享品牌、主题、基础控件和站点导航。后台保留工作台侧栏；小游戏保留玩法区域的独立配色。
5. 保持静态页面输出和公开 URL。共享页头仍应在 HTML 中可见，不依赖运行时注入来生成整页主要内容。
6. 分组迁移，每组整理后再进入下一组，不做一次性目录搬迁或框架替换。

## 前端分层

- **设计基础层**：唯一的颜色、字体、间距、圆角、阴影、层级、主题和焦点状态定义；提供按钮、表单、卡片、弹窗等通用样式。
- **站点外壳层**：品牌区、主导航、移动导航、主题开关、页脚和页面内容宽度。重复外壳使用单一源维护，并生成或保留静态 HTML。
- **页面组层**：主站内容、图片/视频工具、小游戏、认证和运营后台分别维护页面专用布局与交互样式。共享层通过稳定的类名与变量提供基础能力。
- **功能模块层**：按页面组归属入口脚本、可复用模块、Worker 和纯逻辑核心；功能模块不承担站点导航或全局主题规则。
- **静态资源层**：图片、图标、第三方 vendor 文件与游戏资源归入明确类别；路径变化必须保持浏览器可访问 URL 不变，或由现有静态服务提供兼容映射。

## 实施顺序

1. **资产与页面清点**：列出所有静态页面、客户端渲染页面、入口脚本、样式表、Worker、共享导航版本及各自静态服务规则，确定迁移顺序和保留的页面例外。
2. **稳定共享基础**：确定唯一变量来源，合并全站主题和基础控件规则；先统一页头、导航、内容宽度、按钮、表单、卡片和焦点状态。
3. **整理主站与内容页面**：把首页、目录视图、发现/榜单/教程/资讯等主站页面消费同一外壳和基础规则，梳理 `app.js` 与主站样式的职责边界。
4. **整理工具页面**：按图片/视频/实用工具分组页面资源，统一外壳与通用输入、上传、状态和导出控件；保留工具自己的处理逻辑。
5. **整理认证与后台**：认证页面消费共享基础；后台继续使用独立工作台导航与信息密度，但统一主题变量、表单、按钮、表格、弹窗和状态色。
6. **整理小游戏与资源例外**：游戏目录页和游戏外壳消费共享基础；游戏画布、棋盘和第三方游戏资源保留独立主题与资源结构。

页面资源归组以减少认知负担为目标，不以移动文件数量作为完成标准。只有在静态路由、部署打包和现有链接均可保留时才调整物理目录。

## 兼容与边界

- 不改变现有 URL、路由、API、数据库和业务流程。
- 不删除或改名业务脚本依赖的 DOM ID、`data-*` 属性和类选择器，除非同步迁移所有使用点并确认行为兼容。
- 不改写游戏玩法区域、图片/视频处理核心或后台权限逻辑。
- 不增加运行时前端框架。任何构建辅助仅用于维护共享静态片段或资源，不把页面变成客户端路由应用。
- 保持明暗主题、系统主题偏好、移动导航和 `prefers-reduced-motion` 行为。

## 验收标准

- 每个页面组的页面清单、入口资源和例外在仓库中容易定位。
- 页面之间的品牌导航、主题、内容宽度、卡片、按钮、表单和焦点状态遵循同一套来源，不再依赖多个相互覆盖的全局变量副本。
- 页面专用样式只保留必要的布局与功能样式；重复的全站外壳维护成本明显降低。
- 桌面、窄屏、浅色和深色主题下，站点外壳和基础控件保持一致；后台仍清晰体现工作台结构，游戏玩法区仍保留各自风格。
- 现有路由、页面交互、工具处理、游戏操作、认证及后台功能保持可用。
- 发布输出仍是可直接服务的静态 HTML/CSS/JavaScript，线上 URL 不变。

## 非目标

- 不迁移到 React、Vue、Next.js、Vite SPA 或其他前端框架。
- 不重新设计品牌、改变主站信息架构或重写页面文案。
- 不统一后台信息密度或把所有游戏画布改成紫色。
- 不修改后端接口、权限、数据库和部署架构。
