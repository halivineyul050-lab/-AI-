# NeStudio 动态积分计费设计（计价口径待用户选择）

## 已确认问题

当前 server 的 NeStudio provider 设置和 credit_config.modelPrices.nestdutio 只支持每次整数积分。jobs.submit 预留 count=1，成功时 settle(successCount=1)；generator 丢弃模型响应 usage；前端 config.unitCredits 显示每次固定价格。因此仅改页面文字无法实现实际计费。

## 推荐方案：实际 Token 用量

模型输入、输出分别配置每百万 Token 的积分单价，任务开始时保存模型和费率快照。将需求分析、生成及自动修复各轮模型实际返回的 usage 累加；缓存输入如有单独价格则拆分，推理 Token 按服务商 usage 定义去重，不能重复计算。合计后再向上取整一次，不能每轮取整增加扣费。缺少可靠 usage 时不得退回固定20积分或虚构用量。

备选为服务商实际金额换积分，仅在其接口有可信的结算金额字段且币种与换算明确时使用；标准 Chat Completions 的 Token usage 并不代表一定包含实际金额。当前项目没有服务商金额字段或人民币到积分的成本结算规则。

## 用户可见行为

去掉“20积分/次”。提交前展示计价规则、明确标注的预估范围和本次预算上限。输入及已有作品上下文变化后刷新估算，不能把估算写成最终费用。需求分析和生成使用同一费率快照；每轮模型返回后更新已统计用量及金额，不显示虚构的逐秒消耗。完成时显示实际扣费和明细；已有“失败退回”承诺保留。继续修改单独按该轮实际上下文及输出计费。

## 余额与安全边界

钱包新增按明确预算预留与按实际积分结算的能力，保留图片按张计费接口。成功扣费、作品新版本、用量记录在同一财务事务提交；重试及重复回调不得重复扣款。开始前预留用户可见预算，逐轮调用前控制资源，不得事后超预算或让余额变负。修改费率不追溯已开始任务。失败或重启中断释放全部预留，不将服务商错误当用户成功消费。

## 实施与验收范围

增加持久化用量/费率快照和实际费用记录；生成器汇总各轮usage，jobs接入预算与实际结算，后台替换固定价格设置，工作台显示预估/已统计/实际。验证大小需求费用不同、多轮累计只取整一次、修改按实际上下文计费、并发余额、重复请求、未知usage、失败退款、重启恢复，以及不影响现有图片计费。生产仍须以当前线上完整版本为基底，经正式 release-production.sh 发布。

本文件为方案讨论稿，未擅自设置商业费率、修改真实积分或发布代码。用户需先选定 Token 单价或服务商实际金额口径；实际费率由运营方配置。
