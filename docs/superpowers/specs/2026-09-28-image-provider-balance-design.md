# 生图平台余额查询设计

## 目标

在运营后台的生图平台卡片上查看各平台账户余额。解锁平台设置后立即查询，页面可见期间每 60 秒自动刷新，并保留手动查询；若平台没有余额接口或未配置查询参数，后台清楚标记为暂不支持。

## 方案

采用每个平台可配置的余额接口，而不是假定 OpenAI 兼容接口具有统一的余额 API。平台设置增加可选余额查询路径、JSON 余额字段路径和币种字段路径；路径只允许相对当前平台 Base URL 的站内路径。运营人员可依据供应商文档配置这些字段。未配置时不发出网络请求。

用户界面通过管理员会话触发查询。服务端使用已存储的密钥调用该平台接口，解析数值余额和可选币种，返回查询时间。页面不接收或保存密钥。查询失败仅返回经过清理的错误摘要，不展示上游请求头、密钥或原始响应体。余额展示为“余额 + 币种 + 最近查询时间”，并提供手动刷新；页面隐藏时暂停自动查询，重新显示时立即刷新。不以生成调用推算余额。

## 安全与数据

- 查询路由复用现有管理鉴权；更新/配置密钥继续沿用当前最高管理员限制。
- 只允许 HTTPS 的公网平台地址和相对路径，查询目标固定为已保存的平台主机，防止自定义绝对 URL、内网地址及 SSRF。
- 请求超时复用平台超时配置并施加合理上限；限制响应体大小，只接受 JSON 对象和有限长度的字段路径。
- 持久化余额查询配置，不持久化账户余额。查询值仅保存在当前页面内存，并通过定时请求更新，避免在其他会话显示旧值。
- 旧平台记录新增列使用可空或默认空值，现有平台升级后视为未配置；SQLite 与 MariaDB 开发/生产迁移保持一致。

## 验收

1. 支持配置查询路径、余额字段和币种字段；老平台未配置时显示“未配置余额接口”。
2. 手动查询时服务端以 Bearer Key 请求同一平台，前端能显示金额、币种和查询时间，密钥不进入浏览器响应、日志或审计记录。
3. 覆盖成功、无效 JSON/金额、超时、HTTP 错误、缺少配置、鉴权失败和拒绝不安全目标的测试。
4. 现有平台和模型管理、图片生成行为保持不变，完整测试通过。

## 实施范围

仅修改生图平台配置存储与迁移、后台管理 API、平台编辑表单和平台卡片展示，以及对应测试和运维说明。不新增供应商专属 API 猜测；具体端点由平台管理员根据供应商文档配置。
