# 自由生成交互式讲解：产品设计稿

日期：2026-10-14。用户已明确选择“自由生成：任意输入问题，AI生成新演示”。本文保留原始完整设计；2026-10-15已上线基本自由生成、参数交互、修改和链接分享，实际范围及未实现的云历史/持久化任务等以[当前发布验收](../../deployment-explainer-ai-20261015.md)为准，不应将原稿中的所有规划视为已实现。

## 1. 产品定位与方式选择

入口名称：交互讲解。主标题：动手试一试，把问题看明白。副标题：输入你想理解的问题，AI为你创建可以拖动、调节和一步步观察的演示。

用户可以自由提出主题，不限于预置案例。案例仅用于展示输入方式，不作为支持主题白名单。对无法形成有效互动的问题，说明原因并建议具体的改写，不用普通长文冒充交互演示。

三种实现方式比较：固定演示库可靠但主题有限，不符合本次选择；任意HTML/JavaScript生成表达能力强，但隔离、兼容和代码修复成本高；推荐自由生成结构化场景，交给受控渲染器执行。第三种允许AI创建新的主题、布局、图形、参数、状态变化和解释，不执行任意模型代码。

## 2. 入口与创作页面

新增独立页面 /explain，公共导航新增“交互讲解”，首页增加入口。沿用当前紫色设计系统、浅色/深色主题和公共导航。

首页依次展示标题、输入区、案例和我的讲解。描述框占主要位置，示例占位：“为什么月亮会有阴晴圆缺？让我拖动月球的位置，看见月相变化。”上限1000字，保留输入草稿。

输入区包含：问题描述；理解程度（零基础/一般/深入，默认零基础）；讲解方式（自动/参数实验/逐步演示/关系图，默认自动）；主按钮“生成交互讲解”。不在首版增加模型选择、复杂风格配置或文件上传。

下方六个可直接填入的问题：月相变化、掷骰子的概率、冒泡排序、二分查找、二次函数图像、屏幕RGB混色。点击填入，不自动提交。首版保存至少三个已审阅演示供访客免登录试玩。

生成前展示是否需要登录、可用免费次数和历史实测等待区间。没有样本时仅显示“生成时间取决于内容复杂度”，不编造秒数。首次登录返回后保留描述和选项。

## 3. 演示工作台

顶部：标题、AI生成标识、保存状态、全屏、分享。桌面主体左侧约2/3为演示画布和控件，右侧约1/3为当前说明；下方为追问/修改入口。移动端先画布、再控件、再解释，避免细小画布和左右横向滚动。

画布旁统一提供播放/暂停、重置；逐步演示提供上一步/下一步，连续参数提供滑块和数值输入。暂停动画时仍可调整参数。所有核心操作支持键盘，触控不依赖悬停。跟随系统减少动态效果偏好。

解释区域分为“现在发生了什么”“为什么会这样”“试试这样操作”。说明由参数和当前步骤驱动，不是固定文章。用户操作后不调用模型，结果在本地即时更新。

修改入口文案：“还想怎么讲？”示例：讲得更简单、增加对比、把步骤拆开。显示本次修改会创建新版本及剩余次数；保存原版本，生成失败仍可继续使用原演示。首版不提供聊天机器人、源码编辑器或导出可执行HTML。

## 4. 一次完整体验

输入月相问题 → 点击生成 → 展示三个真实阶段“构思演示/搭建互动/检查运行” → 演示就绪 → 拖动月球 → 地球视角月相和说明同步改变 → 输入“给小学生讲” → 创建新版本 → 用户选择分享 → 获取固定版本链接。

月相示意须标明尺寸和距离不按真实比例，并区分太阳照亮的半球与地球观察到的亮面；不能用地球阴影解释普通月相。概率案例随机实验与理论概率同时展示；排序案例必须遵循选定算法步骤。示例将用于验收，不将这些知识点硬编码为唯一可生成主题。

## 5. 生成与运行架构

服务端创建持久化生成任务，模型返回结构化场景定义：标题、学习目标、图形元素、控件、状态变量、初始值、步骤、受限表达式、解释分支、假设和局限。支持SVG图形、连线、文字、数组、坐标轴、曲线、柱状/折线数据和基础动画，组件可自由组合。

受限表达式使用显式AST和数学运算白名单解释执行，不使用eval、Function或任意JavaScript。图形属性、URL、变量数、表达式深度、循环步数、点数、节点数及文本大小均有上限。模型输出作为数据，不能创建任意HTML、外部脚本、表单、iframe或外部资源请求。首版由平台提供受控交互，模型不能访问主站Cookie、存储或账号接口。

校验流程：结构校验 → 表达式与引用校验 → 初始状态及参数边界执行 → 渲染检查。自动修复最多一次，修复后仍失败则明确报错。校验保证结构可运行，不代表知识已经经过人工事实核验。页面展示AI生成、示意假设和问题反馈入口；不能给未核验演示标“科学认证”。无法表达的互动不降级执行任意代码，提示调整问题。

新增独立讲解服务、任务与版本存储，复用现有账号、加密配置与限流基础设施。模型配置支持独立启停、接口、模型和输出上限，不直接套用现有工具推荐助手的系统提示和1200-token限制。服务端保管密钥；候选模型的结构化输出能力需实测，不能根据名称推断支持。

任务状态：queued、planning、building、checking、repairing、ready、failed、cancelled。刷新后恢复原任务；前端断线查询原任务，不自动重复生成。重复提交通过请求幂等标识归并。取消后不自动展示晚到结果。

## 6. 免费次数、保存与分享

建议首版内测采用登录用户每日3次成功生成，案例试玩和已保存演示的操作不消耗次数。次数属于待批准产品规则；本稿不设积分价格。提交时预占次数，同一任务/自动修复不重复占用，失败或取消释放。另设独立的提交频率、并发和资源限制，不能利用失败释放无限调用模型。

成功结果自动保存为私有记录，可重命名、删除、继续修改；用户问题和生成结果不会自动公开。分享需主动点击创建，只公开选定版本的演示内容，不展示邮箱或账号资料。提醒用户检查演示中的个人信息；分享固定版本，不随之后修改改变。

分享页免登录可操作、不可修改源作品，提供“创建我的讲解”。用户可以关闭分享，链接失效；首版公共分享页不被搜索引擎收录，不建立未经审核的公开广场。本人删除作品同时关闭分享；服务端验证权限。首版分享统一初始状态，不暴露草稿和追问历史。

## 7. 错误与反馈

模型未配置：禁用生成，保留案例试玩；排队：显示当前状态及取消；超时/模型拒绝/输出无效：显示明确原因、保留问题并释放次数；不能表达：建议更具体的互动描述；画布运行失败：隔离当前演示并保留已保存版本；分享关闭：明确链接失效。

每个结果提供“内容不准确/操作异常”反馈，携带演示ID及版本，复用现有反馈渠道和邮件通知。记录任务耗时、模型成本及错误类别，日志不输出密钥和用户完整问题。

## 8. 验收与上线边界

验收必须覆盖：至少六个不同主题的真实生成；三个审阅案例的数学/算法状态正确；滑块上下界与重置；桌面/手机/键盘；断线恢复；取消及晚到结果；重复提交；生成失败次数释放；删除/关闭分享；匿名分享与权限；伪造场景输入及表达式资源上限。用户问题自由，但不能声称所有主题都能成功生成。

核心指标：首次生成就绪率、生成后首次操作率、分享率、7日再次使用率；辅助记录耗时和单次成本。先取得内测基线，再设转化目标，不预先声称有增长效果。
