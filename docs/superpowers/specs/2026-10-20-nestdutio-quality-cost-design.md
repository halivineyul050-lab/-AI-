# NeStudio 生成质量与成本核算改造方案（待确认）

## 已核验事实

2026-10-20 对生产进行了只读核查，没有修改线上费率、模型或用户数据。

- 当前模型标识 deepseek-flash，maxTokens=31999，计费模式为 fixed，成功生成 20 积分。
- 常规套餐为 6 元/600 积分、18 元/2000 积分、50 元/6000 积分、100 元/12500 积分；每次 20 积分的收入对应 0.16～0.20 元。首购套餐另有优惠，不能统一用常规套餐推算实际收入。
- 最近 20 个历史任务：16 个 failed、4 个 ready，均未保存实际 Token 用量。该样本跨历史版本，不作为当前版本的基准测试。
- 全部历史失败：输出截断 15、运行检查未通过 4、通用生成失败 3、超时 2。
- 当前生成目标只允许网页资源，不支持 WXML/WXSS 等原生小程序文件。
- Token 模式使用上游 usage，累计后向上取整为整数积分；固定模式不记录用量。前端预估仅按输入文本/旧作品长度和一次输出上限粗算，未覆盖所有规划、逐文件生成和修复调用。
- 当前未配置上游采购单价，也未保存逐请求缓存/推理等账单细项，因此不能核算成本、利润或追溯旧任务实际 Token。

## 推荐实施顺序

### 第一阶段：可核账与网页可用性

1. 用量记录独立于收费模式：逐请求保存任务、阶段、模型、上游实际 usage、重试信息、成功/失败状态；固定收费仍记录用量。缺失或不完整的 usage 明确标注，不能当零成本。
2. 采购成本与用户积分售价分开配置和记录。支持单价币种、计价单位、缓存计价等适用维度，任务保存价格快照；未知单价显示“待配置”，不自行补零或猜测供应商价格。金额使用定点计算。
3. 展示实际请求用量合计、用户收费、退款及可核算成本。估算明确为估算，不再把单次输出上限当完整任务费用。现有历史收费不自动追溯改写。
4. 根据失败样本改生成拆分、单文件大小与续写/修复策略，避免仅靠增大 maxTokens。把用户需求转成可复现验收，覆盖关键流程、错误输入、持久化和手机端；不得只用模型自己生成的简单选择器证明可用。
5. 使用计算器、习惯打卡、报名工具作为首批真实基准；验证核心业务结果和修改后功能保留，再报告质量提升。模型比较需要明确试跑预算。

### 第二阶段：微信原生小程序独立目标

- 区分网页和微信小程序目标，分别使用产物结构、生成规则、验证和导出流程。
- 原生小程序产出 app.json、app.js、页面 JS/JSON/WXML/WXSS 等必要工程文件；不将 HTML 网页当原生小程序交付。
- 浏览器只能提供说明性预览，不能替代微信开发者工具编译与真机验证。登录、云开发、支付等能力需要独立后端与授权配置，不能伪造。
- 原生能力的当前规范以微信官方文档为准；实施前核对工具环境、AppID 模式与测试范围。
