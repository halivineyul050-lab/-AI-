# NeStdutio：自然语言生成并发布可用应用

日期：2026-10-15。状态：用户已确认产品方向，进入详细设计与分阶段实施规划；尚未上线。

## 1. 目标与交付标准

用户描述需求，平台生成网页或手机网页，支持对话修改、真实预览、版本恢复、在线发布和完整源码导出。产品名称按用户要求保留为 **NeStdutio**；主站入口为「创作与效率 → NeStdutio」，建议工作台路由 `/nestdutio`。

“拿到就能用”同时满足：页面能打开、核心操作真实执行、数据按承诺保存、刷新后结果正确、手机可操作、源码能按说明独立运行。只有通过检查的版本才能标记“可发布”。生成了文件、截图或空壳页面不算完成。

首版交付网页与手机网页。微信小程序与可安装 APP 是后续独立适配项目；当前入口不提供不可用的生成按钮，也不把手机网页称为原生 APP。

## 2. 方案比较与选择

1. 纯静态单页生成：交付快，适合展示页和计算器，但无法兑现真实表单收集及共享数据。
2. **浏览器应用 + 平台提供的有限数据能力（选定）**：生成 HTML/CSS/JavaScript；服务端使用经过测试的固定能力，通过声明式配置接入。既能交付可运行作品，又能控制托管成本和权限。
3. 任意全栈项目与任意服务器代码：扩展面广，但要求独立构建、依赖治理、运行容器和完整资源调度。首版不采用。

模型可以生成浏览器代码，但不能生成并在主站执行任意服务器程序、Shell、数据库语句或部署脚本。

## 3. 首版真实支持的作品

| 作品 | 可用能力 | 数据承诺 |
| --- | --- | --- |
| 官网、活动介绍、作品集 | 多页面、链接、响应式布局 | 内容随作品版本发布 |
| 计算器、转换器、交互工具 | 输入、校验、计算、导出结果 | 默认无需后端 |
| 个人清单、记账、习惯工具 | 增删改查、筛选、浏览器本地保存 | 明示“仅当前浏览器保存”，不冒充云同步 |
| 报名、咨询、反馈收集 | 字段校验、真实提交、成功回执、作者查看与导出 | 存在平台数据库，跨设备可管理 |

首版共享数据能力限于：公开访客提交记录、作品作者登录主站后查看和导出。访客不能读取全部记录、任意修改他人数据或自行设置管理身份。跨设备个人账号、复杂协作、支付、短信、第三方业务 API 属于后续能力；需求涉及这些能力时，先列出缺项与替代范围，不能悄悄生成模拟功能。

## 4. 用户流程

1. 输入需求，可附参考图；选择网页或手机网页。案例只用于帮助描述，不代替真实生成。
2. 展示简短需求清单：页面、核心操作、数据方式、外部依赖。普通请求可直接生成；关键依赖缺失时明确说明。
3. 展示预计消耗与当前任务状态：理解需求、生成文件、检查运行、修复、预览就绪。时间估计只能根据实际观测给范围，不能伪造百分比。
4. 成功后左侧继续对话，右侧可操作预览。修改基于当前版本，明确此次影响，保留未要求改动的功能。
5. 发布前显示检查结果、地址、作品公开范围与数据方式；用户点击发布才建立公开访问入口。
6. 修改形成新草稿，旧线上版本持续服务。更新发布后才切换正式版本，失败保留旧版。
7. 用户可下载对应版本源码包、恢复历史版本、下线作品。下线不自动删除已收集的数据；删除作品另行明确确认数据处置。

## 5. 页面与交互

首页：一句话输入框、网页/手机网页选择、真实可运行案例和最近作品。

工作台：左侧约三分之一为需求与对话，右侧为预览；顶部包含作品名、保存状态、桌面/手机切换、版本、下载源码和发布。手机端在对话与预览之间切换，不能压成不可操作的窄双栏。

预览为默认视图；代码与文件作为次级入口。失败时保留当前成功版本，显示失败阶段、是否退回消耗和重试入口，不清空用户输入。

发布面板：选择平台分配地址或自定义域名；显示待验证、证书配置中、检查中、已上线和失败等真实状态。复制链接只在地址真实可用后提供。域名未就绪时不显示假成功。

## 6. 生成、检查与自动修复

生成结果为受限文件清单与作品清单：名称、入口、页面路由、文件内容、数据声明和核心验收场景。文件路径规范化并限制长度、数量和总大小，拒绝绝对路径、目录穿越、符号链接与秘密文件。

固定浏览器依赖白名单；模型不能任意安装包或引用未知 CDN。首版优先浏览器原生 HTML/CSS/JavaScript，减少用户导出后的构建门槛。平台生成的文件不接收服务器凭据。

检查包含：文件完整性、JavaScript 语法、入口和内部资源、运行错误、桌面与手机布局、核心操作。具有数据能力的作品还要实测提交、持久化、读取权限及错误回执。

生成前提取核心验收条件，生成后由固定测试规则与真实浏览器验证；不能仅依赖模型自己声称“通过”。首版最多两次自动修复，均受总任务超时、Token 和资源预算限制。失败不得把坏版本发布出去。

## 7. 数据与项目边界

项目、版本、任务、发布、域名绑定及数据集分别管理。版本文件不可原地覆盖；项目保存当前草稿和当前线上版本指针。

所有作者操作由主站身份鉴权并校验项目归属。托管数据始终由服务端根据作品及数据集身份确定作用域，不信任浏览器传入的 userId、ownerId 或管理标志。公开提交接口限制字段、大小、频率与来源，带幂等标识，防止重复提交。管理接口与公开提交接口分离。

首版不运行任意模型服务端代码。表单等服务端功能使用固定平台运行时与声明式字段配置；迁移或修改字段不得静默删除线上已有记录。

## 8. 预览隔离与托管

预览在隔离 iframe 中执行，禁止获得主站同源权限、读取主站存储或任意导航父页面。需要数据时使用受限、校验来源与项目身份的桥接/能力接口，不能向作品暴露主站登录凭据。

正式作品默认使用与主站分离的无登录 Cookie 托管域名，例如 `<slug>.apps.ontimo.cn`。启用前必须审计现有 Cookie 的 Domain、宿主边界和登录接口；如站点共享父域 Cookie 无法消除，改用独立注册域名。不得将不可信作品直接作为 `ontimo.cn/apps/...` 的同源页面执行。

公开作品配置独立 CSP、访问与上传限制，不能访问主站管理接口或云服务元数据。共享主机不等于共享应用权限；工作目录、文件访问和资源预算分开。生成任务并发、存储、作品访问及公开表单流量均有可配置上限。

## 9. 发布、域名和回滚

默认托管到用户现有服务器上的独立作品存储/托管区域，不进入主站代码目录。先验证现有 CPU、内存、磁盘、反向代理、DNS 与证书能力，再决定实际容量。缺少通配 DNS 或证书时先显示配置缺口，不能声称自动分配域名已可用。

平台子域名：校验和保留 slug，拒绝保留词及冲突；根据经过验证的 DNS/证书配置生成地址。自定义域名：先验证所有权及唯一绑定，再检查解析与 HTTPS；提供明确解析指引，支持解绑及防止遗留域名接管。

作品发布链：版本检查 → 不可变产物入库 → 候选地址健康检查 → 原子切换线上版本 → 从外部访问核验。切换失败恢复旧指针；保留发布记录和回滚入口。发布不能接受用户传入 Shell 或任意目标路径。

**主站平台代码发布**仍严格遵守 `docs/production-release.md`，使用线上完整基底和现有 `/opt/nikai-ai/scripts/release-production.sh`，不直接修改生产应用目录。**用户作品发布**是平台功能，在独立作品区域更新版本；它不能成为绕过主站正式发布流程的入口。

## 10. 源码交付

下载包与预览/发布使用同一版本，包含页面、样式、脚本、所需资源、作品配置、说明和可复现运行方式。只引用随包资源或明确配置的服务，不能依赖私有预览地址、临时文件或平台管理员凭据。

纯静态作品可用标准静态服务器运行。含真实数据能力的作品附固定、经过测试的独立 Node 运行时、锁定依赖、SQLite 数据初始化、环境配置示例和启动命令；默认数据为空，导出真实用户记录是单独的授权操作。

独立运行时为数据管理提供作者身份验证与初始化引导，不使用硬编码默认密码。域名、HTTPS 或第三方服务属于部署配置，说明必须列清。按干净环境执行 README 的命令，完成一次核心操作与重启持久化测试后，才将包标记为可交付。

## 11. 模型、计费与任务恢复

后台提供独立模型开关、服务商配置、超时、输出预算、并发与计费配置；沿用项目现有加密凭据及管理界面模式。可明确继承 AI 助手配置，也可独立配置，不向浏览器暴露密钥。

首次生成、修改、托管用量分别定义计费事件。每次操作先展示消耗再预留，成功只结算一次，平台失败只退回一次；同一操作重试不得重复扣费。具体价格在成本实测后配置，不在设计中捏造。

任务落库并具有幂等键。刷新可恢复状态；服务重启后正确恢复或结束任务及预留额度，不能盲目重放上游调用。错误日志关联任务号和安全错误类型，不打印提示全文、生成源码、表单记录或凭据。

## 12. 分阶段实施与验收

阶段一：工作台、项目版本、自然语言生成、隔离预览、自动检查修复和静态源码导出。

阶段二：独立作品托管、平台地址/子域名、真实发布更新与回滚。此阶段前不向用户宣传“一键上线”已经完成。

阶段三：固定表单/数据运行时、作者数据管理、自定义域名和包含后端的独立源码交付。三阶段共同构成此次完整首版，不以只有生成界面的阶段一冒充最终交付。

必须验收：

- 输入计算工具需求，生成后真实计算、手机可用，下载包在干净环境运行。
- 输入活动报名需求，访客提交后作者另一设备可看到记录；其他作者和匿名访客无法读全部数据。
- 对话修改保留原有能力，可恢复旧版本；修改未发布时线上版本不变。
- 点击发布后外部实际访问成功，平台地址与自定义域名均覆盖 HTTPS 和失败状态。
- 更新失败仍能访问旧版，下线后作品不可继续访问，数据不会被隐式清空。
- 测试非法文件路径、恶意生成代码、跨租户读写、重复提交与结算、资源超限、重启恢复。
- 无效模型配置、生成失败、检查失败、域名未验证时，状态与扣费真实、可解释。

## 13. 实施前核验项

服务器容量、现有 Cookie 域、DNS 管理权限与通配证书尚未在本次设计中实测。它们是明确的实施前检查项，检查结果决定具体承载规模和最终托管域名。任何缺口不得通过假发布、降低权限隔离或复用管理员凭据绕过。

本设计不包含自动上架小程序或原生 APP、不承诺任意第三方服务开箱即用；这些平台需后续独立设计与真实交付验证。
