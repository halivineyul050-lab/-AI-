# Obsidian 公众号初稿导入资讯设计

## 目标

把 `D:\Users\zhanglian2\Documents\Obsidian Vault\公众号日更包\公众号——张练` 根目录中的公众号文章初稿整理为网站资讯，并写入线上 MariaDB。目录内 73 篇 Markdown 中，排除 4 篇标题含“资讯选题池与待确认线索”的材料稿，处理其余 69 篇正式文章。

## 编辑原则

采用保守精修。保留作者的事实、观点、论证顺序和个人表达，不凭空补充经历或未经原稿支持的结论。只修正明显病句、重复表达和影响阅读的草稿痕迹。

每篇删除以下内容：

- YAML front matter 与内部状态字段
- 正文前重复出现的一级标题
- “备选标题”“开头导语”“正文”等编辑阶段包装标题
- 封面图、正文图、配图位置、图片内容、图片说明和图片文案
- Markdown 图片、HTML 图片标签及仅用于承接图片的空段
- 写作要求、编辑备注、待确认提示和发布操作说明
- 公众号点赞、关注、星标、转发、投稿邮箱等平台专属尾注
- 与正文无关的选题讨论、素材清单和重复来源列表

保留有事实支撑作用的来源链接。文章不设置封面图片，正文中不保留任何图片或图片占位。

## 字段映射

- `kind`: `news`
- `topic`: 优先取 front matter 标签中的首个具体主题，无法可靠判断时使用 `AI资讯`
- `title`: 优先使用 front matter 的标题，缺失时使用首个一级标题或清理后的文件名
- `excerpt`: 从清理后正文开头提取完整语义的 80–180 字摘要，不包含 Markdown 标记
- `cover_url`: 空字符串
- `body_text`: 清理后的 Markdown 正文
- `published_date`: front matter 日期，缺失时取文件名前缀日期
- `read_time`: 按中文正文长度估算，最低 1 分钟
- `source_name`: 有明确单一来源时使用来源域名或机构名，否则使用“综合公开资料”
- `source_url`: 有来源链接时使用首个有效的公开 HTTP(S) 链接，否则留空
- `status`: `published`

文章 ID 和 slug 使用发布日期与规范化标题生成的稳定值，重复运行保持不变。

## 数据流

1. 只扫描目标目录根部的 `.md` 文件，不扫描“素材”和“配图”目录。
2. 排除 4 篇选题池材料，解析其余 69 篇的 front matter 和正文。
3. 执行逐篇清理，输出结构化导入文件及审查报告。
4. 自动检查文章数量、标题、正文、发布日期、重复项、图片语法和草稿提示词。
5. 对线上 MariaDB 创建带校验和的备份。
6. 以稳定 ID/slug 执行 upsert；已有同标题或同 slug 的文章更新为整理后的版本，避免重复。
7. 查询线上数据库并检查资讯接口，确认文章数量、无图片字段和正文可读取。

## 质量门槛

- 恰好处理 69 篇正式文章，4 篇选题池不进入网站
- 每篇标题、正文和发布日期非空
- `cover_url` 全部为空
- 正文不存在 Markdown/HTML 图片、配图占位和编辑说明
- 同一标题、ID 或 slug 不重复
- 导入事务失败时整体回滚
- 导入前 MariaDB 备份通过 SHA-256 校验
- 导入后线上资讯接口可读取新文章，网站服务保持健康

## 回滚

导入前记录目标文章的既有行并生成 MariaDB 全量备份。需要回滚时优先恢复本批次涉及的文章；若出现跨表或不可判定问题，使用校验过的全量备份恢复数据库。
