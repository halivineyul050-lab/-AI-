# NeStudio 微信原生小程序独立目标设计

## 范围与选择

用户已确认 A+B：完整原生工程与下载，并包含 AppID 配置、扫码体验衔接和提审引导。2026-10-21 原生生成、目标隔离、工程导出、微信发布面板及官方 CLI 衔接已实现，尚未生产发布。用户目前没有 AppID，微信编译、真实扫码、真机与上传仍待账号及工具就绪后验收。

推荐在现有 NeStudio 工作台增加“网页 / 微信原生小程序”目标，复用项目历史、逐请求用量账本和积分结算，分开产物验证与导出。继续输出 HTML 再放进 web-view 无法满足原生要求；另建完全独立工作台会重复历史和计费逻辑。

## 目标与数据

- 项目创建时固定 target 为 web 或 wechat；旧项目缺省 web。任务、检查点、版本带一致 target，指纹包含 target，禁止在恢复或重试时串用产物。
- 切换目标必须新建项目，保留原项目版本。前端提交、后端查询和导出都验证归属及目标，不能仅依赖提示词判断。
- 通过下一条空闲的 SQLite/MariaDB 迁移保存目标元数据，迁移编号实施前重新核对，避免与其他并行开发冲突。

## 原生产物

独立 schema，入口为 app.json，支持 app.js/app.wxss、project.config.json、页面与组件 JS/JSON/WXML/WXSS、本地图片资源。app.json 注册全部页面，页面/组件配置注册 usingComponents；静态检查引用存在、路径边界、文件数量/体积、JSON 与 JS 语法。

生成规则采用原生 Page/Component、setData、bind 事件和 wx 存储 API，禁止 DOM/window/localStorage、HTML 页面及浏览器 CDN。先支持无后端的计算器、个人习惯与本地数据工具。报名收集到作者后台、用户登录、支付和跨设备同步必须有单独后端与授权合同，不能以本地数据或成功弹窗冒充。

平台生成固定的安全 project.config.json，不接收模型提供的 AppSecret、上传私钥或任意编译脚本。导出 ZIP 为能导入开发者工具的工程，附带运行和验证说明；AppID 由作者在本地开发者工具配置。

## 预览和验收

网页目标继续运行隔离浏览器检查。微信目标在右侧显示工程文件、页面注册关系和当前验证结果，不把网页 iframe 描述成小程序运行效果。

验证分三项分别展示：工程结构检查、微信开发者工具编译、模拟器/真机业务验收。结构通过不能自动标记后两项通过。计算器核对独立数值向量；习惯工具覆盖增加、独立打卡、重启恢复与删除。

当前电脑已安装微信开发者工具 2.01.2510290，路径为 D:/Program Files (x86)/Tencent/微信web开发者工具；cli.bat 可运行帮助。现有服务端口文件存在，但端口当前没有监听，尚未确认登录、项目 AppID 或可用基础库。实施时启动工具并核验真实状态；涉及登录扫码/真机时由用户完成必要操作，不读取或猜测凭据。

生产 Linux 生成服务不能直接假定本地 Windows 开发者工具可调用。原生目标启用前必须确定受信验证执行端及任务回传协议，或明确将其作为“待作者在开发者工具验证的源码导出”产品等级，并在提交前告知收费与交付边界。不能沿用网页的“已通过运行检查”文案。

## 成本和兼容

复用第一阶段逐请求账本、采购价快照与失败退款；原生目标的售价单独配置，未确认前不沿用网页成功收费承诺。原生版本禁用网页托管、域名绑定和 HTML 表单后端接口，导出入口与历史恢复保留。
