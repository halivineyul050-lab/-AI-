# 生图图片传输超时修复

- 发布 ID：`image-transfer-20261009-2`。
- 发布时间：2026-10-09 13:53:39（Asia/Shanghai）。
- 现象：13:34:12 的异步任务正常提交，13:37:13 返回上游超时。修复了 60 秒网关等待后，仍触发 180 秒后端总期限。
- 实测根因：`gpt-image-2`、用户提供的公众号封面提示词、16:9（1792x1024）返回 HTTP 200 约 22 秒，但 Base64 图片响应经平台链路传输极慢，180 秒仅接收约 1.08 MB；600 秒仍未完成，连接被诊断期限中止。服务器 TCP 信息显示重传和大量乱序。简单小图同格式约 17 秒成功，不能代表复杂图片可用。
- 解决方式：无参考图请求优先使用 `response_format=url`；平台返回的 HTTP 图片地址仅升级到同主机 HTTPS 下载，仍通过 safeFetch 的 DNS、私网、端口、凭据和重定向安全检查。不传递平台 API Key 到图片下载请求，不向浏览器暴露平台地址；保持图片格式和大小校验及 Base64 响应兼容。参考图编辑继续使用原格式。
- 超时：平台首响应仍受原配置限制（最多 180 秒）；后续数据传输按连续有数据刷新空闲期限，并设置 600 秒总传输上限。页面查询等待最多 810 秒，任务 15 分钟过期。
